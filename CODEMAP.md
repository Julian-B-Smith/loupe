# CODEMAP — Loupe

Where things are. Moved verbatim from the pre-spinup CLAUDE.md (2026-10-01) and extended with the harness.

## Harness

- `CLAUDE.md`: charter (invariant harness layer + §Domain + knowledge loop).
- `ROADMAP.md`: phase-gated plan; the single source of task state.
- `DECISIONS.md`: append-only index of decisions; content lives in `docs/decisions/`.
- `INDEX.md` / `LIBRARY.md`: knowledge loop.
- `verify`: the oracle (`./verify fast|full|report`). `.kit/`: vendored kit gates (do not edit).

- `.claude/`: hooks, agents (implementer=sonnet, verifier=haiku, critic=opus), provenance skill.

## Project

- `docs/vision.md`: the pipeline, the two-view split, the target experience.
- `docs/visual-grammar.md`: primitives, the claim each makes, audit tests, dialects. Mostly Proposed.
- `docs/decisions/`: decision log.
- `prototype/index.html`: 2D viewer v1 (open in a browser). Hosted copy: https://claude.ai/artifact/9MWcjmEY9umVzobq71a3wW
- `prototype/primitives.html`: gallery of the proposed visual primitives, each with its audit test run live on the
  sample, plus Keep / Revise / Cut verdicts. Hosted copy: https://claude.ai/artifact/Lw7cH6LF7sUgLGCERhgR1Y
- `docs/graph-schema.md`, `schema/`: the data contract (graph, overlay, view, loupe-spec). Example snapshot in
  `schema/examples/horde-sample/`.
- `tools/`: `loupe-check.mjs` (snapshot checker; V9 runs the viewer's layout headless), `loupe-check.test.mjs`
  (mutation tests), `canon.mjs`, `convert-sample.mjs`, `example-cmake-basic.mjs` (build facts → 0.3 example, a
  stand-in until the emitter), `probe-crawl.mjs` (probe crawler, not P1). Run with `npm run check` and `npm test`.
  The HORDE gates (Q-025): `horde-gate.mjs` (one command: clone a named HORDE commit on its terms, crawl twice, leak
  check, probe, parity; `./verify full`), `parity.mjs` (probe vs crawl, every probe edge classed),
  `horde-parity-explained.json` (the hand-written reasons, pinned to a commit, reviewed like code),
  `horde-gate-waiting.json` (gates that fail for a reason outside Loupe, printed by `full`), `gate.test.mjs` (the
  committed report, in `fast`). The report lives beside the snapshot: `design/prototype/snapshots/horde-crawl/{gate,parity}.json`.
  The stress cases (Q-029): `stress-gen.mjs` (the ten cases of docs/design-handoff.md, deterministic; nine committed in
  `design/prototype/snapshots/stress/`, the 4,000-file one never) and `stress.test.mjs` (byte-compare, render at every
  level of detail with the meter balanced, a geometry check per case; in `fast`).
- `schema/examples/horde-probe/`: a real crawl of HORDE (commit c64cfdbc), produced by the probe.
- `schema/examples/cmake-basic-0.3/`: the only 0.3 example: targets, builds/depends/generates edges, configs.
- `docs/spinup-brief.md`: what the `/spinup` agent needs to wire Loupe into the autonomous system.
- `docs/design-handoff.md`: the contract with the Claude Design agent: required tokens, the `loupe-spec`
  block per primitive, screens, stress cases. Published doc: https://claude.ai/code/artifact/090409e4-c614-47e7-aa44-cebbea549775
- `docs/design-links.md`: pinned links and versions of the design agent's artifacts.
- `prototype/data/sample-horde.js`: invented HORDE-shaped sample graph. Not crawled. Shared by both pages.
- `design/`: in-house since ADR 0022 (was the Claude Design agent's lane). `HANDOFF.md` (delivery note), `prototype/` (v4),
  `system/` (design-system snapshot: tokens.json, one README per primitive), `tokens.css` (hand-made until Q-007).
- `docs/design-review-v4.md`: infrastructure's review of delivery v4.
- `viewer/index.html`: the testbench landing page (no doctype; wrapped by the artifact host and by `tools/serve.mjs`).
- `tools/serve.mjs`: `npm run view`. Zero-dependency, read-only, loopback-only server. `ALIASES` maps the published
  paths `design/proto/` and `v1/`, because the artifact host reserves `prototype` as a path segment.
- `.claude/launch.json`: `loupe-view` for the app's browser pane.
- `design/prototype/matrix.js`: the matrix lens (ADR 0029, Q-030): one section or a pair as files × files, each edge in
  exactly one place (a cell, a row's out-margin, a column's in-margin, or the outside chip). `render.js` `renderMatrix`
  draws it when `state.matrix` is set in the Design view; `inspect.js` `heldEdges` opens each place.
- `design/prototype/split.js`: Flow and Design side by side (ADR 0030, Q-031): `paneState` (what each pane renders and
  is metered with; Flow gets no Design mode), `followPan` (a selection a pane does not show pans it there, zoom kept),
  `worse` (the header meter shows the worse pane). `index.html` owns the two panes, the divider and the pointer;
  `render.js` `map.locate` says where a selection is in a frame. Checks: `tools/stress.test.mjs`, the Q-031 block.
- `design/prototype/specs.js`: GENERATED by `tools/specs.mjs` (`npm run specs`) from every `loupe-spec` block in
  `design/system/components/*/README.md` (Q-036); do not edit. The tally (render.js §4b) and the matrix (`matrix.js`
  `MX`, `renderMatrix`) read their sizes, parts and colours from it; `render.test.mjs` fails when it is stale.
- `design/prototype/story.js`, `works.js`, `stories/`: the "How it works" view (ADR 0025). `stories/<repo>-<commit>.json`
  holds agent-written stories (stand-in format); `story.js` applies Julian's edits and does the accounting;
  `works.js` draws it. `lens.js`: focus lenses (ADR 0019); the Operational lens seeds from the product targets when the graph has them (Q-009). Tests: `tools/{history,lens,story}.test.mjs`.
- `crawler/`: the P1a crawler, TypeScript run natively by Node 24 (no compiler). `build.ts` is the build layer
  (CMake File API + expanded JSON trace, scratch dir outside the tree, always deleted); `syntax.ts` is the syntax
  layer (a line scanner for includes and their `#if` conditions, with a census; tree-sitter for parse-error counts;
  resolution per site); `dialect.ts` assigns file roles (defaults, the dsp-plugin dialect, graph rules, the repo's config) and draws the GUI bridge; `langs.ts` is the languages layer (Python, JS, TypeScript with tsconfig aliases, HTML, shell: imports, references, data and generated files); `graph.ts` emits graph.json (0.3.2) with the inventory;
  `conformance.ts` compares declared target dependencies with observed includes; `cli.ts` (`npm run crawl --
  build|syntax <repo>` or `crawl <repo> --out <dir>`); `build.test.ts`, `syntax.test.ts`, `graph.test.ts` (gated in `./verify fast`). `grammars/`: the C and C++
  grammar .wasm files, vendored and pinned by sha256 in `GRAMMARS.json` (refresh steps in its README).
- `fixtures/cmake-basic/`: crawler fixture with two declared configurations; its goldens are
  `fixtures/cmake-basic.{facts,syntax,graph,conformance}.golden.json` (rewrite only with
  `--update` on the matching test, reviewed).
